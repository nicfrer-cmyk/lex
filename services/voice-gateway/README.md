# Voice Gateway

שרת הקול של מרכז השיחות. **אינו חלק מהפריסה של ה-CRM.**

## הפרדה שאסור לטשטש

| | CRM | Voice Gateway |
|---|---|---|
| איפה רץ | Netlify + Supabase | שרת Linux פרטי |
| סוג | Serverless / static | Docker, תהליכים ארוכי-חיים |
| מה עושה | נתונים, מסכים, לוגיקה עסקית | טלפוניה, אודיו, זמן אמת |
| נפרס ע"י | `git push` | `docker compose up -d` |

השירות הזה **לא נפרס ל-Netlify ולא כפונקציה Serverless**, ולא בגלל העדפה:
שיחת טלפון היא חיבור מתמשך של דקות עם זרם אודיו דו-כיווני. Serverless מנתק
אחרי שניות, אין לו מצב בין קריאות, ואין לו socket פתוח. Asterisk בפרט הוא
דמון שמחזיק רישום SIP חי — הוא לא יכול "להתעורר לבקשה".

## מה כבר עובד בלי השירות הזה

הכול, חוץ משיחות טלפון אמיתיות. ה-CRM מריץ את מרכז השיחות במלואו — סוכן,
שער כלים, תמלול, סיווג, יצירת לידים ומשימות ופגישות, ציר זמן, סיכומים —
דרך **מצב בדיקה**. ראה `docs/AI_CALL_CENTER.md`.

השירות הזה מוסיף שכבה אחת: להביא קול אמיתי מקו טלפון אל אותו מנוע.

## ארכיטקטורה

```
   קו SIP של הספק
        │
        ▼
   ┌──────────┐   ARI (WebSocket)   ┌───────────────┐
   │ Asterisk │◄───────────────────►│  Orchestrator │
   │    22    │                     │   (Python)    │
   └──────────┘   External Media    └───────┬───────┘
                  (RTP / WS audio)          │
                                            │ HTTPS + HMAC
                                            ▼
                                   ┌──────────────────┐
                                   │  CRM (Supabase)  │
                                   │  voice-gateway   │
                                   │  Edge Function   │
                                   └──────────────────┘
```

Asterisk אחראי על הטלפוניה בלבד: לקבל שיחה, לענות, לגשר, להעביר אודיו
החוצה ולקבל אודיו בחזרה, לנתק, להחזיק, ובעתיד להעביר. הוא **לא** מכיר AI.

ה-Orchestrator אחראי על השיחה: STT → CRM (סוכן + כלים) → TTS. הוא **לא**
מכיר SQL, אין לו service_role key, ואין לו גישה ישירה למסד הנתונים.

## Providers

הכול מאחורי ממשקים (`app/stt`, `app/llm`, `app/tts`, `app/telephony`).
ברירת המחדל היא Self-Hosted; החלפת ספק היא משתנה סביבה, לא שינוי קוד.

| שכבה | ברירת מחדל | ממומש | מתוכנן |
|---|---|---|---|
| STT | `mock` | mock, faster-whisper | — |
| LLM | `crm` (הסוכן רץ ב-CRM) | crm, mock, ollama, vllm | — |
| TTS | `mock` | mock | Local TTS כשייבחר מנוע עברית |
| Telephony | `asterisk` | asterisk (ARI), mock | — |

**אין כאן ספק TTS עברי מומצא.** לא נבחר מנוע, ולכן `MockTTSProvider` הוא
ברירת המחדל והוא מצהיר על עצמו ככזה. מנוע שמחזיר שקט ומדווח "הצלחה" גרוע
ממנוע שמודה שאינו קיים.

## הפעלה

```bash
cd services/voice-gateway
cp .env.example .env          # ומלא את הערכים
docker compose up -d
./scripts/healthcheck.sh
```

בלי `VOICE_GATEWAY_SECRET` ו-`CRM_BASE_URL` השירות עולה, מדווח על עצמו
כלא-מוגדר, ואינו מנסה להתחבר. זה מכוון: התחלת עבודה עם הגדרות חסרות
מייצרת תקלות שקשה לאתר.
